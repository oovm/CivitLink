# GG 引擎 UI 系统架构文档

## 1. 概述

GG 引擎的 UI 系统分为两个独立的子系统：**编辑器 UI** 和 **游戏 UI**。这两个系统在设计理念、技术实现和使用场景上有显著差异，分别参考了 Unity 的 UI Toolkit 和 uGUI 的设计哲学。

### 1.1 设计目标

- **编辑器 UI**：提供高性能、声明式的 UI 系统，用于开发编辑器界面和工具窗口
- **游戏 UI**：提供灵活、功能丰富的 UI 系统，支持 3D 空间和复杂动画效果
- **资源分离**：确保编辑器 UI 和游戏 UI 的资源相互隔离，避免混淆
- **性能优化**：针对不同场景的性能需求进行专门优化

## 2. 编辑器 UI 系统

### 2.1 设计理念

编辑器 UI 系统采用**声明式**设计，参考 Unity 的 UI Toolkit，基于 Valkyrie Widget 语言（.widget 文件）开发。它的核心设计理念是：

- **基于文档对象模型 (DOM)**：将 UI 视为一个独立的文档树
- **结构与样式分离**：使用 .widget 文件定义结构，使用样式系统定义样式
- **高性能渲染**：采用预分配-动态更新的渲染模式，减少 CPU 开销
- **组件化**：支持自定义组件和复合组件

### 2.2 核心组件

#### 2.2.1 Widget 特质

`Widget` 是编辑器 UI 组件的基础特质，定义了组件的基本行为：

```rust
pub trait Widget: Any + Send + Sync {
    fn render_template(&self) -> oak_voc::TemplateNode;
    fn script_setup(&mut self);
    fn get_style(&self) -> Option<&str>;
    fn get_id(&self) -> &str;
    fn handle_event(&mut self, event: &GuiEvent, ctx: &mut EventContext);
    fn children(&self) -> Vec<Arc<RwLock<dyn Widget>>>;
    fn on_mount(&mut self);
    fn on_update(&mut self);
    fn on_cleanup(&mut self);
    fn is_dirty(&self) -> bool;
    fn clear_dirty(&mut self);
    fn get_dirty_flags(&self) -> DirtyFlag;
    fn mark_dirty(&mut self, flag: DirtyFlag);
    fn usage_hints(&self) -> UsageHints;
    fn build(&mut self, tree: &mut UiTree) -> GResult<UiNodeId>;
    fn update(&self, tree: &mut UiTree);
    fn node_id(&self) -> Option<UiNodeId>;
}
```

#### 2.2.2 内置组件

- **Layout**：布局组件，支持 Flexbox 布局系统
- **Stack**：栈式布局组件，支持水平和垂直方向
- **Button**：按钮组件，支持点击事件和状态管理
- **Text**：文本组件，支持富文本和字体样式
- **Image**：图片组件，支持纹理和颜色
- **Input**：输入组件，支持文本输入和验证
- **Panel**：面板组件，容器组件
- **ScrollView**：滚动视图组件，支持滚动内容

#### 2.2.3 事件系统

编辑器 UI 事件系统基于事件冒泡机制，支持以下事件类型：

- **鼠标事件**：点击、双击、悬停、离开
- **键盘事件**：按键按下、释放、按住
- **触摸事件**：触摸开始、移动、结束
- **自定义事件**：用户定义的事件类型

#### 2.2.4 状态管理

编辑器 UI 使用 `Signal` 系统进行状态管理，支持：

- **单向数据流**：状态变化通过信号传播
- **响应式更新**：组件自动响应状态变化
- **状态共享**：多个组件可以共享同一个状态

#### 2.2.5 样式系统

编辑器 UI 样式系统参考 CSS，支持：

- **选择器**：基于组件类型、ID 和类名的选择器
- **样式属性**：布局、颜色、字体、边框等
- **继承**：样式可以继承自父组件
- **优先级**：样式优先级规则

### 2.3 渲染系统

编辑器 UI 渲染系统采用**预分配-动态更新**模式：

1. **预分配 GPU 缓冲区**：在初始化时分配大型顶点和索引缓冲区
2. **网格生成**：将 UI 元素转化为网格数据
3. **动态更新**：仅更新变化的部分，避免重建整个网格
4. **批处理**：使用统一的着色器，减少绘制调用

### 2.4 底层渲染模型对比

| 对比维度 | Editor UI（保留模式） | Game UI（合并-重建模式） |
|---------|---------------------|------------------------|
| 核心哲学 | 持久化数据，变化时局部更新 | 动态构建，每帧重新拼合 |
| 网格生成 | 初始化时写入 GPU 缓冲区，运行时原地修改 | 每帧在 CPU 端动态合并临时网格 |
| 内存策略 | 静态预分配，零 GC 压力 | 动态分配临时网格对象，GC 负载高 |
| CPU 开销 | 静止时几乎为零；更新时极小 | 每帧均有重建开销，变化频繁时 CPU 负担重 |
| GPU 开销 | 稳定且极低（1~2 Draw Call） | 依赖 Canvas 合并效果，可能产生多次 Draw Call |
| Draw Call 策略 | Uber-Shader 合并为 1 次 Draw Call | Canvas 按材质/纹理批次合并 |
| 3D 世界空间 UI | 不支持 | 原生支持 WorldSpace 模式 |
| 复杂动画/特效 | 有限支持 | 完整支持（可接入粒子系统、后处理） |
| 布局引擎 | Yoga/Flexbox（脏标记触发） | Canvas 坐标系（每帧计算） |
| GPU 驱动变换 | UsageHints（位移/颜色/缩放/透明度） | 不支持（CPU 侧重建） |

### 2.6 .widget 文件格式

.widget 文件是编辑器 UI 的声明式定义文件，使用 Valkyrie Widget 语言编写：

```widget
<template>
  <Layout id="main" class="container">
    <Button id="submit" class="primary">Submit</Button>
    <Text id="message" class="info">Hello, World!</Text>
  </Layout>
</template>

<script>
  using gg_editor::ui::widgets::{Layout, Button, Text};
</script>

<style>
  .container {
    padding: 16px;
  }
</style>
```

### 2.8 编译器集成

编辑器 UI 的 `.widget` 文件由 `gg-compiler-widget` 编译器模块负责编译。编译器遵循 GG 引擎的统一编译管线，将 Widget 文件编译为可运行时加载的产物。

#### 编译流程

```
.widget 文件 → VxParser → TemplateAst + ScriptAst + StyleAst → IR 生成 → WidgetArtifact
```

**编译阶段**：

1. **解析阶段**：使用 `VxParser` 将 Widget 文件解析为 Template、Script、Style 三部分
2. **语义分析阶段**：组件类型检查、属性验证、事件绑定验证
3. **IR 生成阶段**：生成 TemplateIr、ScriptIr、StyleIr
4. **代码生成阶段**：生成 TemplateBundle、BytecodeModule、StyleBundle
5. **产物打包阶段**：打包为 WidgetArtifact

**组件注册系统**：

编译器通过 `ComponentRegistry` 进行组件类型检查，所有内置组件和编辑器专用组件都在编译器中注册，实现编译期类型安全。

```rust
pub struct ComponentRegistry {
    components: HashMap<String, ComponentSchema>,
    builtins: HashSet<String>,
}
```

**运行时加载**：

`GuiRuntime` 负责加载编译后的 Widget 产物，构建 UI 节点树并执行脚本。

```rust
impl GuiRuntime {
    pub fn load_widget(&mut self, artifact: &WidgetArtifact) -> GResult<Entity> {
        let ui_tree = self.build_ui_tree(&artifact.template)?;
        let entity = self.create_entity_from_tree(&ui_tree)?;
        // 加载脚本和样式
        Ok(entity)
    }
}
```

Widget 编译器的详细架构设计，请参见 [Widget 编译器扩展计划](../roadmaps/compiler-extra.md)。

## 3. 游戏 UI 系统

### 3.1 设计理念

游戏 UI 系统采用**基于 GameObject 和 Component** 的设计，参考 Unity 的 uGUI，用于开发游戏内 UI。它的核心设计理念是：

- **融入游戏世界**：将 UI 视为游戏世界的一部分
- **3D 空间支持**：支持在 3D 空间中渲染 UI
- **动画和特效**：支持复杂的动画和视觉特效
- **组件化**：基于 ECS 架构，支持组件组合

### 3.2 核心组件

#### 3.2.1 Canvas 组件

`Canvas` 是游戏 UI 的根容器，负责管理所有 UI 元素的渲染：

- **渲染模式**：屏幕空间覆盖、屏幕空间相机、世界空间
- **排序**：控制 UI 元素的渲染顺序
- **批处理**：合并相同材质的 UI 元素，减少绘制调用

#### 3.2.2 RectTransform 组件

`RectTransform` 是游戏 UI 元素的变换组件，用于控制位置、旋转、缩放和锚点：

- **锚点**：定义 UI 元素的锚定方式
- **枢轴**：定义 UI 元素的旋转和缩放中心
- **尺寸**：控制 UI 元素的大小

#### 3.2.3 内置组件

- **Image**：图片组件，支持纹理和颜色
- **Text**：文本组件，支持富文本和字体样式
- **Button**：按钮组件，支持点击事件和状态管理
- **InputField**：输入字段组件，支持文本输入
- **Slider**：滑动条组件，支持数值调节
- **Toggle**：开关组件，支持布尔值状态
- **Dropdown**：下拉菜单组件，支持选项选择
- **ScrollRect**：滚动矩形组件，支持内容滚动
- **GridLayoutGroup**：网格布局组件，支持网格排列
- **HorizontalLayoutGroup**：水平布局组件，支持水平排列
- **VerticalLayoutGroup**：垂直布局组件，支持垂直排列
- **ContentSizeFitter**：内容大小适配器，根据内容自动调整大小
- **AspectRatioFitter**：纵横比适配器，保持指定的纵横比

#### 3.2.4 事件系统

游戏 UI 事件系统基于射线检测，支持以下事件类型：

- **指针事件**：点击、悬停、拖拽
- **键盘事件**：按键按下、释放、按住
- **触摸事件**：触摸开始、移动、结束
- **自定义事件**：用户定义的事件类型

#### 3.2.5 动画系统

游戏 UI 动画系统支持：

- **属性动画**：控制 UI 元素的属性变化
- **状态机动画**：基于状态机的复杂动画
- **补间动画**：支持各种缓动函数
- **动画事件**：在动画关键帧触发事件

### 3.3 渲染系统

游戏 UI 渲染系统采用**合并-重建**模式：

1. **网格生成**：为每个 UI 元素生成独立的网格
2. **网格合并**：将使用相同材质的网格合并成大网格
3. **批处理**：减少绘制调用
4. **脏标记**：仅在 UI 元素变化时重建网格

### 3.4 动静分离优化

Game UI 的动静分离策略是提升渲染性能的关键手段，通过将频繁变化的 UI 与静态 UI 分离到不同 Canvas，避免不必要的网格重建。

**核心策略：**

- **频繁变化的 UI**（动态血条、计时器、动画元素等）放置在动态 Canvas 中，每帧执行网格重建
- **静态 UI**（背景面板、标签文本、装饰元素等）放置在静态 Canvas 中，跳过每帧重建
- 静态 Canvas 仅在自身元素发生变化时才触发重建，其余帧直接复用上次的合并网格

**分离方式：**

1. **手动分离**：开发者在编辑器中将 UI 元素分配到不同的 Canvas，主动控制动静分离
2. **自动建议**：`CanvasBatchDebugger` 工具追踪每个元素的脏标记频率，当超过 50% 的元素频繁变脏时，建议进行动静分离

**性能收益：**

- 静态 Canvas 跳过每帧重建，CPU 开销接近于零
- 动态 Canvas 仅包含少量频繁变化的元素，重建开销大幅降低
- 整体 Draw Call 数量可能增加（多个 Canvas），但 CPU 端重建开销显著减少

### 3.5 3D 空间支持

游戏 UI 支持在 3D 空间中渲染，通过设置 `Canvas` 的渲染模式为 **World Space**：

- **位置**：UI 元素可以放置在 3D 空间的任何位置
- **旋转**：UI 元素可以朝向任何方向
- **缩放**：UI 元素的大小可以根据距离自动调整
- **交互**：支持 3D 空间中的鼠标和触摸交互

### 3.6 工具支持

游戏 UI 提供以下工具支持：

- **场景编辑器集成**：在场景编辑器中编辑游戏 UI
- **预制体系统**：支持 UI 元素的复用
- **动画编辑器**：用于创建和编辑 UI 动画
- **性能分析器**：用于分析 UI 性能

## 4. 资源管理系统

### 4.1 设计理念

资源管理系统负责管理编辑器 UI 和游戏 UI 的资源，确保资源隔离和高效加载：

- **资源分离**：编辑器 UI 和游戏 UI 的资源相互隔离
- **统一接口**：提供统一的资源加载和管理接口
- **热更新**：支持资源的热更新，无需重启应用
- **缓存**：智能缓存机制，提高资源加载速度
- **内存管理**：自动管理资源内存，避免内存泄漏

### 4.2 资源类型

- **编辑器 UI 资源**：.widget 文件、样式文件、编辑器专用纹理和字体
- **游戏 UI 资源**：UI 预制体、纹理、字体、材质、动画

### 4.3 资源加载

资源管理系统支持以下加载方式：

- **同步加载**：阻塞式加载，适用于初始化时的资源
- **异步加载**：非阻塞式加载，适用于运行时的资源
- **预加载**：提前加载可能需要的资源
- **按需加载**：仅在需要时加载资源

### 4.4 资源热更新

资源管理系统支持资源的热更新：

- **自动检测**：自动检测资源文件的变化
- **实时更新**：无需重启应用，立即应用资源变化
- **回滚**：支持资源更新失败时回滚到之前的版本

## 5. 性能优化策略

### 5.1 编辑器 UI 性能优化

- **批处理**：合并相同材质的 UI 元素，减少绘制调用
- **缓存**：缓存布局计算结果和渲染数据
- **多线程**：使用多线程处理复杂计算
- **内存池**：使用内存池减少内存分配
- **延迟加载**：仅在需要时加载资源

### 5.2 游戏 UI 性能优化

- **动静分离**：将频繁变化的 UI 与静态 UI 拆分到不同 Canvas
- **批处理**：合并相同材质的 UI 元素，减少绘制调用
- **LOD**：根据距离调整 UI 元素的细节级别
- **缓存**：缓存渲染数据和计算结果
- **内存池**：使用内存池减少内存分配
- **GPU 驱动**：将部分操作交给 GPU 处理

### 5.3 性能分析工具

- **性能统计**：实时统计 UI 性能指标
- **瓶颈分析**：自动分析性能瓶颈
- **优化建议**：提供针对性的优化建议
- **可视化工具**：直观展示性能数据

## 9. 结论

GG 引擎的 UI 系统通过分离编辑器 UI 和游戏 UI，针对不同场景提供了优化的解决方案。编辑器 UI 采用声明式设计，提供高性能的编辑器界面开发体验；游戏 UI 采用基于 GameObject 的设计，支持复杂的 3D 效果和动画。两者通过资源管理系统和性能优化策略，确保了系统的高效运行。

通过参考 Unity 的 UI Toolkit 和 uGUI 的设计理念，GG 引擎的 UI 系统在保持易用性的同时，提供了强大的功能和性能。未来，我们将继续优化和扩展 UI 系统，为开发者提供更好的开发体验。
