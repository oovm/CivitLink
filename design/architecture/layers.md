# 元游戏引擎架构层级

GG 元游戏引擎采用清晰的分层架构，从编译时框架到运行时逐层构建，确保各层职责明确、依赖关系清晰。基于 Gnostic 神话隐喻，元引擎框架（太一）作为超越的本源，通过流溢产生具体游戏引擎（德穆革），最终由游戏创造者（执权者）创作游戏世界。

```mermaid
    end

    运行时层 -->|依赖| 元引擎框架层
```

## 元引擎框架层 (Meta-Engine Framework - 编译时)

元引擎框架层是整个架构的基石，对应 Gnostic 神话中的**太一（The One）**。它以潜能的形式存在于编译时，提供所有构建具体游戏引擎所需的全部能力。该层不直接创建游戏世界，而是通过流溢产生德穆革（具体游戏引擎）。

### 职责

- 职责概述
元引擎框架层提供编译时工具链，为资深玩家提供构建具体游戏引擎的基础能力。它是不可知、不可说的本源，包含万物生成的基始。

### 子模块

#### ECS 核心 (gg-ecs)
- **职责**：提供通用的 Entity-Component-System 实现，不绑定任何游戏逻辑
- **技术选型**：基于 `bevy_ecs` 封装
- **核心能力**：
  - 实体创建/销毁、组件添加/移除、查询迭代
  - 通过 `Schedule` 和 `SystemSet` 组织系统执行顺序
  - 支持并行系统调度
  - 事件系统集成

#### 资源系统 (gg-asset)
- **职责**：统一资源加载接口，支持异步加载、热重载，与具体文件格式解耦
- **核心能力**：
  - 资源引用计数与缓存管理
  - 资源热重载机制
  - 支持多种资源格式（图片、音频、字体等）

#### 调度器 (gg-schedule)
- **职责**：组织和执行系统
- **核心能力**：
  - 调度标签和系统集
  - 系统执行顺序管理
  - 并行调度支持

#### 世界管理 (gg-world)
- **职责**：游戏世界的创建、销毁和管理
- **核心能力**：
  - 整合 ECS 世界、资源服务器和反射注册表
  - 多世界管理支持

#### 反射系统 (gg-reflection)
- **职责**：提供动态类型查询和属性编辑功能
- **技术选型**：基于 `bevy_reflect` 实现
- **核心能力**：
  - 类型注册和查询
  - 属性编辑器支持

#### 类型定义 (gg-types)
- **职责**：提供共享类型定义

#### 宏定义 (gg-macros)
- **职责**：提供实用宏，简化开发

### 与其他层的交互
- 向上：为运行时层提供核心能力
- 静态编译：所有组件在编译时链接到最终引擎可执行文件中

## 运行时层 (Runtime Layer)

运行时层提供虚拟机和中间表示支持。

### 职责

- 职责概述
提供虚拟机执行环境和中间表示（IR），支持 Mod 脚本的加载和执行。

### 子模块

#### 虚拟机 (gg-vm)
- **职责**：嵌入轻量级脚本运行时，定义安全的 Rust-脚本通信接口
- **技术选型**：Wasmtime（桌面）+ wasmi（轻量）
- **核心能力**：
  - 沙箱环境管理
  - 脚本 API 暴露给 gg 脚本
  - 内存安全隔离
  - 动态模块加载

#### 中间表示 (gg-ir)
- **职责**：提供中间表示，用于脚本编译和优化

### 与其他层的交互
- 向下：依赖元引擎框架层
- 数据流动：框架层 → 运行时层 → 脚本执行

## 层级间依赖关系

```mermaid
graph TD
    subgraph 运行时层[运行时层 (Runtime Layer)]
        运行时依赖[依赖 frameworks]
    end

    subgraph 元引擎框架层[元引擎框架层 (Meta-Engine Framework)]
        frameworks子模块[frameworks 子模块]
    end

    运行时层 -->|依赖| 元引擎框架层
```

### 依赖规则

1. **单向依赖**：每一层只能依赖其下层的抽象，不能反向依赖
2. **接口隔离**：上层通过 trait/接口访问下层能力，不直接依赖具体实现
3. **模块解耦**：同一层内的模块之间保持低耦合，通过 ECS 世界和事件通信

### 数据流

1. **初始化流程**：Meta-Engine → Runtime
2. **运行时更新**：ECS 系统调度 → 脚本执行
3. **脚本执行**：游戏事件 → VM API 调用 → ECS 世界操作 → 系统响应

## 神话隐喻映射表

| 诺斯替概念 | 架构组件 | 职责描述 |
|----------|---------|---------|
| **太一（The One）** | 元引擎框架层（Meta-Engine Framework） | 不可名状的绝对本源，超越一切限定，通过流溢产生德穆革。在编译时静态存在，提供所有潜能。 |
| **德穆革（Demiurge）** | 具体游戏引擎（静态可执行文件） | 由太一流溢而出，按照某种理念（插件组合）创造并统治特定的游戏世界。它既非全知亦非全善，仅能实现有限类型的游戏（如Galgame、STG）。 |
| **执权者（Archons）** | 游戏创造者（开发者/设计师） | 德穆革的助手，掌管不同领域。他们使用德穆革提供的工具（编辑器）来设计具体的游戏世界，并决定世界中的规则与内容。 |
| **普累若麻（Pleroma）** | 游戏项目（数据与脚本的总和） | 充满灵性的完整性领域，包含所有潜在的实体与事件。执权者通过编辑端在此领域工作。 |
| **物质世界（Kosmos）** | 运行时客户端（Runtime） | 玩家直接体验的显现世界，是普累若麻在物质层面的投影。受德穆革设定的物理规则（引擎系统）约束。 |
| **流溢（Emanation）** | 引擎插件 | 从德穆革向外流散的功能片段（如渲染、物理、UI），每个插件对应一种宇宙力量。 |
| **异端知识（Gnosis）** | Mod脚本（gg） | 高级玩家获得的灵性知识，能够突破德穆革设定的常规限制，直接干预世界运行。 |
| **神圣火花** | DLC / HMR补丁 | 执权者注入世界的新内容或即时启示，使世界不断丰盈。 |
