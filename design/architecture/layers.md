# 元游戏引擎架构层级

GWG 元游戏引擎采用清晰的分层架构，从核心框架到编辑器界面逐层构建，确保各层职责明确、依赖关系清晰。

## 整体层次结构

```
┌─────────────────────────────────────────────────────────────┐
│                    Editor Framework                          │
│  编辑器框架：编辑器UI组件、属性编辑器、场景视图、资源浏览器       │
├─────────────────────────────────────────────────────────────┤
│                    Engine Plugin Framework                   │
│  引擎插件框架：插件trait、注册表、构建器、清单处理               │
├─────────────────────────────────────────────────────────────┤
│                    Modules (内置功能模块)                     │
│  渲染、物理、动画、音频、UI、输入、网络等功能模块                  │
├─────────────────────────────────────────────────────────────┤
│                    Runtime Layer                             │
│  运行时层：应用生命周期、场景管理、预制体系统、序列化            │
├─────────────────────────────────────────────────────────────┤
│                    Virtual Machine Layer                     │
│  虚拟机层：虚拟机核心、Wasmtime/wasmi后端、脚本API、语言绑定   │
├─────────────────────────────────────────────────────────────┤
│                    Platform Abstraction Layer                │
│  平台抽象层：窗口管理、输入抽象、图形抽象、音频抽象、文件系统抽象 │
├─────────────────────────────────────────────────────────────┤
│                    Core Layer                                │
│  核心层：ECS核心、资源管理、系统调度、世界管理、反射系统          │
└─────────────────────────────────────────────────────────────┘
```

## 核心层 (Core Layer)

核心层提供引擎的基础能力，是整个架构的基石。

### 模块职责

#### ECS (Entity-Component-System)
- 基于 `bevy_ecs` 封装，提供高性能的实体组件系统
- 支持并行系统调度
- 提供实体创建/销毁、组件添加/移除、查询迭代等核心操作
- 通过 `Schedule` 和 `SystemSet` 组织系统执行顺序

#### 资源管理 (Asset)
- 统一资源加载接口
- 支持异步加载、缓存管理、资源引用计数
- 提供资源热重载机制
- 支持多种资源格式（图片、音频、字体等）

#### 系统调度 (Schedule)
- 扩展 ECS 系统调度能力
- 支持系统依赖关系声明
- 提供系统阶段划分（PreUpdate, Update, PostUpdate 等）
- 支持条件系统执行

#### 世界管理 (World)
- 管理 ECS World 生命周期
- 支持多个独立的 World 实例
- 提供资源（Resource）存取接口
- 事件系统集成

#### 反射系统 (Reflection)
- 基于 `bevy_reflect` 实现动态类型信息
- 支持运行时组件属性访问和修改
- 编辑器属性编辑的基础
- 支持动态组件创建

## 平台抽象层 (Platform Abstraction Layer)

平台抽象层屏蔽底层操作系统和运行环境的差异，为上层提供统一接口。

### 模块职责

#### 窗口管理 (Window)
- 基于 `winit` 封装跨平台窗口创建
- 窗口生命周期管理
- 窗口大小、位置、标题等属性控制
- 多窗口支持（可选）

#### 输入抽象 (Input)
- 统一键盘、鼠标/触摸、游戏手柄事件接口
- 桌面端：使用 `winit` 和 `gilrs`
- 移动端：触摸事件、传感器支持
- H5：DOM 事件封装
- 小游戏：小游戏 API 事件适配

#### 图形抽象 (Graphics)
- 基于 `wgpu` 封装，统一渲染管线
- Surface 创建和管理
- 跨平台图形 API 支持：
  - 桌面：Vulkan/Metal/DX12
  - 移动端：平台原生图形 API
  - H5：WebGL2/WebGPU
  - 小游戏：小游戏 Canvas 上下文

#### 音频抽象 (Audio)
- 统一音频播放控制接口
- 支持常见格式（mp3, ogg, wav）
- 桌面/移动端：使用 `kira` 或 `rodio`
- H5：Web Audio API
- 小游戏：小游戏音频接口

#### 文件系统抽象 (Filesystem)
- 统一文件读写、目录遍历接口
- 平台特定实现：
  - 桌面：直接映射操作系统文件系统
  - 移动端：应用沙盒目录
  - H5：HTTP 请求 + IndexedDB 缓存
  - 小游戏：小游戏文件系统 API

#### 时间抽象 (Time)
- 跨平台系统时间获取
- 帧时间、delta 时间计算
- 计时器和定时器支持

## 运行时层 (Runtime Layer)

运行时层整合核心层和平台抽象层，提供完整的应用运行能力。

### 模块职责

#### 应用生命周期 (App)
- 统一应用启动、运行、退出流程
- 平台生命周期事件处理
- 主循环管理
- 帧率控制

#### 场景管理 (Scene)
- 场景加载和切换
- 场景序列化和反序列化
- 场景嵌套和引用
- 场景过渡动画

#### 预制体系统 (Prefab)
- 预制体定义和实例化
- 预制体重载和继承
- 预制体实例修改跟踪
- 预制体嵌套支持

#### 序列化 (Serialization)
- 基于 `serde` 的序列化框架
- 支持多种格式（RON/JSON/YAML）
- ECS 世界和场景的序列化
- 配置文件读写

## 虚拟机层 (Virtual Machine Layer)

虚拟机层提供 gwg 脚本运行环境，支持游戏逻辑的动态扩展。

### 模块职责

#### 虚拟机核心 (Core)
- 定义虚拟机统一接口
- 沙箱环境管理
- 内存安全隔离
- 错误处理机制

#### Wasmtime 后端 (Wasmtime)
- 基于 `wasmtime` 的 JIT 编译运行时
- 桌面平台高性能执行
- WASI 支持（受限）
- 动态模块加载

#### Wasmi 后端 (Wasmi)
- 轻量级解释器后端
- 嵌入式平台和资源受限环境
- 低内存占用
- 跨平台一致性

#### 脚本 API (API)
- 暴露给脚本的 Rust API
- ECS 世界访问接口
- 资源操作接口
- 事件发送和监听
- 时间和随机数等工具接口

#### 语言绑定 (Bindings)
- 脚本语言绑定生成
- 类型安全的 API 映射
- 文档生成

## 引擎插件框架 (Engine Plugin Framework)

引擎插件框架提供插件组合和引擎构建能力。

### 模块职责

#### 插件 Trait (Plugin)
- 定义插件统一接口
- 插件生命周期钩子
- 插件依赖声明
- 插件配置支持

#### 注册表 (Registry)
- 插件注册和管理
- 组件类型注册
- 资源类型注册
- 系统注册

#### 构建器 (Builder)
- 链式 API 构建引擎
- 插件添加和配置
- 功能开关（如编辑器支持）
- 平台特性配置

#### 清单处理 (Manifest)
- 引擎配置文件解析
- 插件清单管理
- 版本兼容性检查
- 依赖关系解析

## 编辑器框架 (Editor Framework)

编辑器框架提供可视化编辑能力，仅在桌面平台启用。

### 模块职责

#### 编辑器 UI 组件 (UI)
- 基于 `egui` 的编辑器界面
- 可复用 UI 组件库
- 主题和样式系统
- 布局管理

#### 属性编辑器 (Inspector)
- 组件属性可视化编辑
- 基于反射系统的自动 UI 生成
- 自定义编辑器支持
- 数组、字典等复杂类型编辑

#### 场景视图 (Scene View)
- 3D/2D 场景渲染
- 实体选择和变换
- Gizmo 工具
- 相机控制

#### 资源浏览器 (Asset Browser)
- 资源文件浏览和管理
- 资源预览
- 资源导入导出
- 资源搜索和筛选

#### 编辑器插件系统 (Editor Plugin)
- 编辑器功能扩展
- 自定义面板
- 自定义工具
- 编辑器事件监听

### UI 模块 (UI)

## 层级间依赖关系

```
┌─────────────────────────────────────────────────────────────┐
│                    Editor Framework                          │
│              (依赖 Engine 和 Modules)                        │
└─────────────────────────────────────────────────────────────┘
                          │
                          ▼
┌─────────────────────────────────────────────────────────────┐
│                    Engine Plugin Framework                   │
│              (整合 Runtime 和 Modules)                       │
└─────────────────────────────────────────────────────────────┘
                          │
                          ▼
┌─────────────────────────────────────────────────────────────┐
│                    Modules (内置功能模块)                     │
│              (依赖 Runtime 层)                               │
└─────────────────────────────────────────────────────────────┘
                          │
                          ▼
┌─────────────────────────────────────────────────────────────┐
│                    Runtime Layer                             │
│              (整合 Core 和 Platform)                         │
└─────────────────────────────────────────────────────────────┘
          │                           │
          ▼                           ▼
┌───────────────────┐       ┌───────────────────┐
│  Virtual Machine  │       │Platform Abstraction│
│      Layer        │       │      Layer         │
└───────────────────┘       └───────────────────┘
          │                           │
          └──────────────┬────────────┘
                         ▼
              ┌───────────────────┐
              │    Core Layer     │
              └───────────────────┘
```

### 依赖规则

1. **单向依赖**：每一层只能依赖其下层的抽象，不能反向依赖
2. **接口隔离**：上层通过 trait/接口访问下层能力，不直接依赖具体实现
3. **模块解耦**：同一层内的模块之间保持低耦合，通过 ECS 世界和事件通信
4. **平台无关**：Core、Runtime、VM 等上层完全平台无关，所有平台差异由 Platform 层封装

### 数据流

1. **初始化流程**：Core → Platform → Runtime → Modules → Engine → Editor
2. **运行时更新**：平台输入 → Runtime → ECS 系统调度 → Modules 执行 → 渲染输出
3. **脚本执行**：游戏事件 → VM API 调用 → ECS 世界操作 → 系统响应
