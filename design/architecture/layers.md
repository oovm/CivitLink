# 元游戏引擎架构层级

GWG 元游戏引擎采用清晰的分层架构，从编译时框架到编辑器界面逐层构建，确保各层职责明确、依赖关系清晰。基于 Gnostic 神话隐喻，元引擎框架（太一）作为超越的本源，通过流溢产生具体游戏引擎（德穆革），最终由游戏创造者（执权者）创作游戏世界。

## 整体层次结构

```
┌─────────────────────────────────────────────────────────────┐
│              编辑器框架层 (Editor Framework)                      │
│  编辑器UI组件、属性编辑器、场景视图、资源浏览器、编辑器插件系统      │
├─────────────────────────────────────────────────────────────┤
│              引擎插件框架层 (Engine Plugin Framework)            │
│  插件trait、注册表、构建器、清单处理、插件组合机制              │
├─────────────────────────────────────────────────────────────┤
│              功能模块层 (Modules)                               │
│  渲染、物理、动画、音频、UI、输入、网络等功能模块                  │
├─────────────────────────────────────────────────────────────┤
│              运行时层 (Runtime Layer)                          │
│  应用生命周期、场景管理、预制体系统、序列化、虚拟机集成              │
├─────────────────────────────────────────────────────────────┤
│              平台抽象层 (Platform Abstraction Layer)            │
│  窗口管理、输入抽象、图形抽象、音频抽象、文件系统抽象、时间抽象  │
├─────────────────────────────────────────────────────────────┤
│              元引擎框架层 (Meta-Engine Framework - 编译时)          │
│  ECS核心、资源系统、虚拟机集成、平台抽象、插件注册与组合机制        │
└─────────────────────────────────────────────────────────────┘
```

## 元引擎框架层 (Meta-Engine Framework - 编译时)

元引擎框架层是整个架构的基石，对应 Gnostic 神话中的**太一（The One）**。它以潜能的形式存在于编译时，提供所有构建具体游戏引擎所需的全部能力。该层不直接创建游戏世界，而是通过流溢产生德穆革（具体游戏引擎）。

### 职责

- 职责概述
元引擎框架层提供编译时工具链，为资深玩家提供构建具体游戏引擎的基础能力。它是不可知、不可说的本源，包含万物生成的基始。

### 子模块

#### ECS 核心 (ECS Core)
- **职责**：提供通用的 Entity-Component-System 实现，不绑定任何游戏逻辑
- **技术选型**：基于 `bevy_ecs` 封装
- **核心能力**：
  - 实体创建/销毁、组件添加/移除、查询迭代
  - 通过 `Schedule` 和 `SystemSet` 组织系统执行顺序
  - 支持并行系统调度
  - 事件系统集成

#### 资源系统 (Resource System)
- **职责**：统一资源加载接口，支持异步加载、热重载，与具体文件格式解耦
- **核心能力**：
  - 资源引用计数与缓存管理
  - 资源热重载机制
  - 支持多种资源格式（图片、音频、字体等）

#### 虚拟机集成 (VM Integration)
- **职责**：嵌入轻量级脚本运行时，定义安全的 Rust-脚本通信接口
- **技术选型**：Wasmtime（桌面）+ wasmi（轻量）
- **核心能力**：
  - 沙箱环境管理
  - 脚本 API 暴露给 gwg 脚本
  - 内存安全隔离
  - 动态模块加载

#### 平台抽象 (Platform Abstraction)
- **职责**：提供平台抽象的接口定义
- **核心能力**：
  - 统一的文件系统、输入、渲染、音频抽象 trait
  - 平台无关的接口定义
  - 使上层代码无需关心底层实现

#### 插件注册与组合机制 (Plugin Registration & Composition)
- **职责**：允许开发者将多个功能插件组合成一个完整引擎
- **核心能力**：
  - 插件 trait 定义
  - 插件注册与管理
  - 插件依赖关系解析
  - 插件之间通过 ECS 世界通信

### 与其他层的交互
- 向下：定义接口，由平台抽象层实现具体平台逻辑
- 向上：为运行时层提供核心能力
- 静态编译：所有插件在编译时链接到最终引擎可执行文件中

## 平台抽象层 (Platform Abstraction Layer)

平台抽象层屏蔽底层操作系统和运行环境的差异，为上层提供统一接口。对应 Gnostic 神话中太一的“遍在性”，使其能显现于不同物质载体（Windows、macOS、移动端、Web）。

### 职责

- 职责概述
为上层提供统一的平台接口，屏蔽不同操作系统和运行环境的差异，确保引擎能适配 Windows、macOS、iOS、Android、H5、微信小游戏等主要平台。

### 子模块

#### 文件系统抽象 (Filesystem)
- **职责**：统一文件读写、目录遍历接口
- **平台实现**：
  - 桌面：直接映射操作系统文件系统
  - 移动端：应用沙盒目录（如 `Documents/`）
  - H5：HTTP 请求 + IndexedDB 缓存
  - 微信小游戏：小游戏文件系统 API

#### 输入抽象 (Input)
- **职责**：统一键盘、鼠标/触摸、游戏手柄事件接口
- **技术选型**：
  - 桌面：`winit` + `gilrs`
  - 移动端：触摸事件、传感器支持
  - H5：DOM 事件封装
  - 小游戏：小游戏 API 事件适配

#### 图形抽象 (Graphics)
- **职责**：统一渲染管线，基于 `wgpu` 封装
- **平台支持**：
  - 桌面：Vulkan/Metal/DX12
  - 移动端：平台原生图形 API
  - H5：WebGL2/WebGPU
  - 小游戏：小游戏 Canvas 上下文

#### 音频抽象 (Audio)
- **职责**：统一音频播放控制接口
- **技术选型**：
  - 桌面/移动端：`kira` 或 `rodio`
  - H5：Web Audio API
  - 小游戏：小游戏音频接口

#### 时间与线程抽象 (Time & Thread)
- **职责**：统一获取系统时间、休眠、线程生成
- **注意事项**：
  - H5 环境无法创建原生线程，需使用 `wasm-bindgen` 的 `spawn_local` 模拟异步任务
  - ECS 系统应设计为单线程调度（兼容 Web 环境）

### 与其他层的交互
- 向下：直接与操作系统/运行环境交互
- 向上：为运行时层提供统一的平台接口
- 平台无关：Core、Runtime、VM 等上层完全平台无关，所有平台差异由本层封装

## 运行时层 (Runtime Layer)

运行时层整合核心层和平台抽象层，提供完整的应用运行能力。对应 Gnostic 神话中德穆革创造世界的法则（ECS 系统）。

### 职责

- 职责概述
整合元引擎框架层和平台抽象层，提供应用生命周期、场景管理、预制体系统、序列化等运行时核心能力。

### 子模块

#### 应用生命周期 (App)
- **职责**：统一应用启动、运行、退出流程
- **核心能力**：
  - 平台生命周期事件处理
  - 主循环管理
  - 帧率控制
  - 编辑器/运行时模式切换

#### 场景管理 (Scene)
- **职责**：场景加载和切换
- **核心能力**：
  - 场景序列化和反序列化
  - 场景嵌套和引用
  - 场景过渡动画
  - 多个独立场景的管理

#### 预制体系统 (Prefab)
- **职责**：预制体定义和实例化
- **核心能力**：
  - 预制体重载和继承
  - 预制体实例修改跟踪
  - 预制体嵌套支持

#### 序列化 (Serialization)
- **职责**：基于 `serde` 的序列化框架
- **核心能力**：
  - 支持多种格式（RON/JSON/YAML）
  - ECS 世界和场景的序列化
  - 配置文件读写
  - 游戏项目数据加载

#### 虚拟机集成 (VM Integration)
- **职责**：集成 gwg 虚拟机到运行时
- **核心能力**：
  - 脚本加载和执行
  - 脚本与 ECS 世界的桥接
  - 脚本热重载支持
  - 沙箱环境管理

### 与其他层的交互
- 向下：依赖元引擎框架层和平台抽象层
- 向上：为功能模块层提供运行时基础
- 数据流动：平台输入 → Runtime → ECS 系统调度 → 模块执行 → 渲染输出

## 功能模块层 (Modules)

功能模块层提供可复用的游戏功能组件，对应 Gnostic 神话中德穆革的流溢（Emanation）。每个插件对应一种宇宙力量。

### 职责

- 职责概述
提供可复用的游戏功能组件，包括渲染、物理、动画、音频、UI、输入、网络等功能模块。

### 子模块

#### 渲染模块 (Rendering)
- **职责**：提供渲染核心能力
- **子模块**：
  - 渲染核心：渲染管线、Surface 管理
  - 2D 渲染：精灵、精灵动画、文本渲染
  - 3D 渲染：网格、材质、光照
  - 相机系统

#### 物理模块 (Physics)
- **职责**：提供物理引擎集成
- **技术选型**：基于 Rapier
- **子模块**：
  - 2D/3D 物理引擎
  - 碰撞检测
  - 刚体模拟
  - 关节系统
  - 物理事件

#### 动画模块 (Animation)
- **职责**：提供动画系统
- **子模块**：
  - 动画核心系统
  - 精灵动画
  - 变换动画
  - 骨骼动画
  - 状态机系统

#### 音频模块 (Audio)
- **职责**：提供音频播放能力
- **子模块**：
  - 音频播放器
  - 混音器
  - 空间音频
  - 音频事件

#### UI 模块 (UI)
- **职责**：提供 UI 系统
- **子模块**：
  - UI 核心系统
  - 基础控件（按钮、文本、图片等）
  - 布局系统
  - 交互处理

#### 输入模块 (Input)
- **职责**：提供输入处理能力
- **子模块**：
  - 键盘输入
  - 鼠标输入
  - 触摸输入
  - 游戏手柄输入
  - 输入映射

#### 网络模块 (Network, 可选)
- **职责**：提供网络能力
- **子模块**：
  - 网络核心
  - 客户端
  - 服务器
  - 同步机制

### 与其他层的交互
- 向下：依赖运行时层
- 向上：为引擎插件框架层提供功能组件
- 模块通信：同一层内的模块之间保持低耦合，通过 ECS 世界和事件通信

## 引擎插件框架层 (Engine Plugin Framework)

引擎插件框架层提供插件组合和引擎构建能力，对应 Gnostic 神话中德穆革按照特定理念（引擎插件组合）创造世界。

### 职责

- 职责概述
提供插件组合和引擎构建能力，由资深玩家（引擎开发者）使用元引擎框架，选择一组插件，通过简单的 `main.rs` 组装而成。

### 子模块

#### 插件 Trait (Plugin)
- **职责**：定义插件统一接口
- **核心能力**：
  - 插件生命周期钩子
  - 插件依赖声明
  - 插件配置支持
  - 组件、系统、资源注册

#### 注册表 (Registry)
- **职责**：插件注册和管理
- **核心能力**：
  - 插件注册和管理
  - 组件类型注册
  - 资源类型注册
  - 系统注册

#### 构建器 (Builder)
- **职责**：链式 API 构建引擎
- **核心能力**：
  - 插件添加和配置
  - 功能开关（如编辑器支持）
  - 平台特性配置
  - 示例代码：
  ```rust
  use meta_engine::prelude::*;
  use galgame_plugin::GalgamePlugin;
  use audio_plugin::AudioPlugin;

  fn main() {
      EngineBuilder::new()
          .add_plugin(GalgamePlugin)
          .add_plugin(AudioPlugin)
          .with_editor(true)
          .build()
          .run();
  }
  ```

#### 清单处理 (Manifest)
- **职责**：引擎配置文件解析
- **核心能力**：
  - 引擎配置文件解析
  - 插件清单管理
  - 版本兼容性检查
  - 依赖关系解析

### 与其他层的交互
- 向下：整合运行时层和功能模块层
- 向上：为编辑器框架层提供引擎基础
- 静态编译：所有插件在编译时链接到最终引擎可执行文件中

## 编辑器框架层 (Editor Framework)

编辑器框架层提供可视化编辑能力，仅在桌面平台启用，对应 Gnostic 神话中执权者进行创造的神圣工坊。

### 职责

- 职责概述
提供可视化编辑能力，执权者（游戏创造者）在此处进行创造，连接普累若麻（游戏项目），允许对世界进行未受物质限制的编辑。

### 子模块

#### 编辑器 UI 组件 (UI)
- **职责**：提供编辑器界面
- **技术选型**：基于 `egui` + `eframe`
- **核心能力**：
  - 可复用 UI 组件库
  - 主题和样式系统
  - 布局管理

#### 属性编辑器 (Inspector)
- **职责**：组件属性可视化编辑
- **核心能力**：
  - 基于反射系统的自动 UI 生成
  - 自定义编辑器支持
  - 数组、字典等复杂类型编辑

#### 场景视图 (Scene View)
- **职责**：3D/2D 场景渲染
- **核心能力**：
  - 实体选择和变换
  - Gizmo 工具
  - 相机控制

#### 资源浏览器 (Asset Browser)
- **职责**：资源文件浏览和管理
- **核心能力**：
  - 资源预览
  - 资源导入导出
  - 资源搜索和筛选

#### 编辑器插件系统 (Editor Plugin)
- **职责**：编辑器功能扩展
- **核心能力**：
  - 自定义面板
  - 自定义工具
  - 编辑器事件监听

### 与其他层的交互
- 向下：依赖引擎插件框架层和功能模块层
- 平台支持：仅在桌面平台启用（H5 可考虑轻量版基于浏览器的编辑器，但功能受限）
- 编辑器与运行时共享大部分代码，通过 feature flag 编译

## 层级间依赖关系

```
┌─────────────────────────────────────────────────────────────┐
│              编辑器框架层 (Editor Framework)                      │
│              (依赖 Engine Plugin Framework 和 Modules)              │
└─────────────────────────────────────────────────────────────┘
                          │
                          ▼
┌─────────────────────────────────────────────────────────────┐
│              引擎插件框架层 (Engine Plugin Framework)          │
│              (整合 Runtime 和 Modules)                       │
└─────────────────────────────────────────────────────────────┘
                          │
                          ▼
┌─────────────────────────────────────────────────────────────┐
│              功能模块层 (Modules)                           │
│              (依赖 Runtime)                                   │
└─────────────────────────────────────────────────────────────┘
                          │
                          ▼
┌─────────────────────────────────────────────────────────────┐
│              运行时层 (Runtime Layer)                          │
│              (整合 Core 和 Platform)                         │
└─────────────────────────────────────────────────────────────┘
          │                           │
          ▼                           ▼
┌───────────────────┐       ┌───────────────────┐
│  元引擎框架层     │       │  平台抽象层         │
│  (Meta-Engine)    │       │  (Platform)        │
└───────────────────┘       └───────────────────┘
          │                           │
          └──────────────┬────────────┘
                         ▼
              ┌───────────────────┐
              │   操作系统/运行环境 │
              └───────────────────┘
```

### 依赖规则

1. **单向依赖**：每一层只能依赖其下层的抽象，不能反向依赖
2. **接口隔离**：上层通过 trait/接口访问下层能力，不直接依赖具体实现
3. **模块解耦**：同一层内的模块之间保持低耦合，通过 ECS 世界和事件通信
4. **平台无关**：Core、Runtime、VM 等上层完全平台无关，所有平台差异由 Platform 层封装

### 数据流

1. **初始化流程**：Meta-Engine → Platform → Runtime → Modules → Engine → Editor
2. **运行时更新**：平台输入 → Runtime → ECS 系统调度 → Modules 执行 → 渲染输出
3. **脚本执行**：游戏事件 → VM API 调用 → ECS 世界操作 → 系统响应
4. **编辑器交互**：用户操作 → Editor UI → ECS 世界修改 → 系统响应 → 渲染更新

## 神话隐喻映射表

| 诺斯替概念 | 架构组件 | 职责描述 |
|----------|---------|---------|
| **太一（The One）** | 元引擎框架层（Meta-Engine Framework） | 不可名状的绝对本源，超越一切限定，通过流溢产生德穆革。在编译时静态存在，提供所有潜能。 |
| **德穆革（Demiurge）** | 具体游戏引擎（静态可执行文件） | 由太一流溢而出，按照某种理念（插件组合）创造并统治特定的游戏世界。它既非全知亦非全善，仅能实现有限类型的游戏（如Galgame、STG）。 |
| **执权者（Archons）** | 游戏创造者（开发者/设计师） | 德穆革的助手，掌管不同领域。他们使用德穆革提供的工具（编辑器）来设计具体的游戏世界，并决定世界中的规则与内容。 |
| **普累若麻（Pleroma）** | 游戏项目（数据与脚本的总和） | 充满灵性的完整性领域，包含所有潜在的实体与事件。执权者通过编辑端在此领域工作。 |
| **物质世界（Kosmos）** | 运行时客户端（Runtime） | 玩家直接体验的显现世界，是普累若麻在物质层面的投影。受德穆革设定的物理规则（引擎系统）约束。 |
| **流溢（Emanation）** | 引擎插件 | 从德穆革向外流散的功能片段（如渲染、物理、UI），每个插件对应一种宇宙力量。 |
| **异端知识（Gnosis）** | Mod脚本（gwg） | 高级玩家获得的灵性知识，能够突破德穆革设定的常规限制，直接干预世界运行。 |
| **神圣火花** | DLC / HMR补丁 | 执权者注入世界的新内容或即时启示，使世界不断丰盈。 |
