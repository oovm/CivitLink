# 架构概览

本项目是一个元游戏引擎框架，定位为编译时框架，通过插件组合机制生成具体的游戏引擎，支持多平台分发。在诺斯替（Gnostic）宇宙观的隐喻下，**太一（gg）** 是超越的源头，**德穆革（具体游戏引擎）** 是有限的世界造物主，**执权者（游戏创造者）** 管理各自的世界，共同构建一个可扩展的游戏创造宇宙。

> 关于 Gnostic 神话隐喻的详细解释，请参考 [Gnostic 架构文档](/gnostic/overview)。

## 元引擎作为编译时框架的总体架构

元引擎框架采用静态与动态分离的设计思想，分为三个层次，对应诺斯替神话中的三层宇宙结构：

### 各层次职责

#### 1. 元引擎框架（太一）

- **ECS核心**：万物生成的基始，一切实体与关系的雏形
- **资源系统**：统一资源加载接口，支持异步加载、热重载
- **反射系统**：提供动态类型查询和属性编辑功能
- **调度器**：组织和执行系统
- **世界管理**：游戏世界的创建、销毁和管理
- **平台抽象层**：屏蔽操作系统和运行环境的差异
- **插件注册与组合机制**：流溢的通道

#### 2. 具体游戏引擎（德穆革）

- 由资深玩家使用元引擎框架，选择一组插件静态编译而成
- 包含 GG Editor（跨平台 GUI 开发框架）和运行时模式（世界法则）
- 每位德穆革拥有固定的能力范围（如Galgame、STG、横版闯关）

#### 3. 游戏实例（游戏世界）

- **编辑端**：灵性蓝图，执权者在此进行创造，使用 GG Editor 开发 GUI 界面
- **运行时客户端**：物质显现，玩家直接体验的世界，包含原生 GUI 界面
- **服务器端**（可选）：宇宙法则，维持多人世界的真实性与连续性

## 运行时与多平台分发架构

在已有静态编译框架基础上，增加平台抽象层和构建/分发策略，确保引擎能适配 Windows、macOS、iOS、Android、H5、微信小游戏等主要平台：

    B -->|游戏数据包 + DLC/Mod 跨平台分发| C
    
    subgraph A1[元引擎框架组件]

### 平台抽象层职责

平台抽象层屏蔽操作系统和运行环境的差异，为上层提供统一接口，包含以下子模块：

- **文件系统抽象**：统一接口访问各平台存储
- **输入抽象**：统一处理按键、鼠标/触摸、游戏手柄等事件
- **渲染抽象**：基于 `wgpu` 统一图形渲染，服务游戏渲染和 Game UI System
- **GUI 抽象**：仅服务 Editor UI Toolkit，处理各平台原生 GUI 系统差异
- **音频抽象**：统一播放控制，支持常见格式
- **时间与线程抽象**：统一获取系统时间、休眠、线程生成
- **动态链接与虚拟机支持**：确保脚本虚拟机能在目标平台运行

### 各平台分发形态

| 平台      | 分发形式                              | 说明                                          |
| ------- | --------------------------------- | ------------------------------------------- |
| Windows | `.exe` 安装程序或便携版                   | 包含所有插件和运行时，可独立运行                            |
| macOS   | `.app` 或 `.dmg`                   | 需签名以通过 Gatekeeper                           |
| iOS     | `.ipa`（通过 TestFlight 或 App Store） | 需 Apple 开发者证书；游戏数据包需通过 iTunes 文件共享或 App 内下载 |
| Android | `.apk` 或 `.aab`（Google Play）      | 需签名；支持外部存储读取游戏数据包                           |
| H5      | 静态文件（HTML + JS + WASM）            | 部署在 Web 服务器上，通过浏览器访问                        |
| 微信小游戏   | 小游戏代码包（包含 WASM 和适配层 JS）           | 需通过微信小游戏审核，遵循小游戏规范                          |

## 项目整体结构：Cargo Workspace 设计

项目采用 Cargo Workspace 结构，按功能分组组织模块：

- **projects/core/**: 核心抽象与基础类型，包括 ECS 核心、资源系统、反射系统、调度器、世界管理等
- **projects/compiler/**: 编译器相关模块，包括编译流水线、脚本语言前端、AOT 编译后端等
- **projects/editor/**: Editor UI Toolkit，包括 GUI 框架核心、GUI 编译器、GUI 运行时等
- **projects/runtime/**: 运行时相关模块，包括系统调度器、宿主服务接口、HMR 状态迁移等
- **projects/platforms/**: 平台特定胶水层，包括 Windows/macOS/Linux、WebAssembly/WebGL 和 iOS/Android
- **projects/plugins/**: 官方提供的领域专用插件模块，包括视觉小说/对话系统插件、瓦片地图与碰撞插件等
- **projects/engines/**: 具体游戏引擎实现，如 Galgame、STG、Platformer 等
- **examples/**: 示例，展示如何使用 gg 引擎定制各环节

## 核心模块架构

### ECS 模块

ECS（Entity-Component-System）是 GG 元引擎的核心框架，采用自研实现，提供高性能、数据驱动的游戏对象系统。

- **实体（Entity）**：游戏世界中对象的唯一标识符
- **组件（Component）**：纯数据结构，附加在实体上
- **系统（System）**：纯逻辑函数，操作具有特定组件的实体
- **资源（Resource）**：全局单例数据，例如配置、时间等

### 资源模块

资源模块提供统一的资源加载、管理和热更新功能，支持编辑器UI和游戏UI的资源分离。

- **资源（Asset）**：游戏中使用的数据，例如图片、音频、模型等
- **句柄（Handle）**：对资源的安全引用
- **资源服务器（AssetServer）**：负责资源的加载和管理
- **资源系统（AssetSystem）**：作为 ECS 系统运行，定期检查热更新

### 世界管理模块

世界管理模块提供游戏世界的创建、销毁和管理功能，整合了 ECS 世界、资源服务器和反射注册表。

- **游戏世界（GameWorld）**：整合 ECS 世界、资源服务器和反射注册表
- **世界管理器（WorldManager）**：负责创建、管理和销毁多个游戏世界
- **场景序列化**：支持游戏场景的保存和加载

### 反射模块

反射模块提供动态类型查询和属性编辑功能，基于 `bevy_reflect` 实现。

- **反射注册表（ReflectionRegistry）**：管理所有可反射类型的信息
- **属性编辑器（PropertyEditor）**：提供动态编辑可反射类型属性的能力

### 调度器模块

调度器模块提供扩展的系统调度功能，定义了标准的游戏执行阶段和系统集。

- **调度标签（ScheduleLabel）**：标识不同的执行阶段
- **系统集（SystemSet）**：组织相关的系统

## 设计原则

### 1. ECS作为统一核心

借鉴Unity的DOTS架构，所有游戏逻辑最终都通过ECS系统执行，确保性能和数据驱动。ECS世界提供统一的实体、组件、系统模型，所有插件和Mod都基于此模型交互。

### 2. 明确的语言分工

**Rust 语言职责：**
- 构建游戏引擎核心，提供原生能力
- 与平台直接交互，处理底层系统
- 实现性能关键部分，如渲染、物理、资源管理
- 构建编译时框架和平台抽象层
- 提供安全、高效的底层实现

**脚本语言职责：**
- 处理所有游戏逻辑，包括游戏状态、AI行为、事件处理
- 通过 hook 式接口与引擎交互
- 实现游戏系统、UI逻辑、Mod和DLC内容
- 支持热更新和动态内容扩展
- 提供灵活、易用的游戏开发环境

### 3. 插件化架构

参考Unreal的模块系统，每个功能模块独立编译，引擎构建时静态链接，保证运行时性能。插件通过 ECS 世界通信，实现松耦合。

### 4. 平台抽象层

借鉴Godot的跨平台设计，通过trait抽象各平台差异，上层代码无需关心底层实现。平台抽象层包含文件系统、输入、渲染、GUI、音频、时间与线程等子模块。

### 5. 静态与动态分离

- **编译时（Rust）**：元引擎框架 + 插件组合 → 生成具体引擎可执行文件
- **运行时（脚本）**：游戏数据包 + DLC/Mod → 动态加载，无需重新编译引擎

### 6. 不同层次玩家各司其职

- **普通玩家**：通过配置数据和编写剧本（DLC）就能创作游戏，无需编程
- **高级玩家**：使用脚本编写Mod，实现更复杂的自定义逻辑
- **资深玩家**：基于元引擎框架开发新的引擎插件或全新引擎（Rust代码），静态编译后发布

## 总结

通过Gnostic神话的透镜，gg元引擎架构展现出深层的象征结构：太一作为超越源头，德穆革作为有限造物主，执权者作为世界管理者，玩家作为灵性寻求者。每一层都既独立又相连，共同构成一个可扩展、跨平台的游戏创造宇宙。

**核心设计理念：明确的语言分工**

- **Rust** 作为引擎核心语言，负责与平台交互，提供原生能力，处理性能关键部分，确保安全高效的底层实现
- **脚本语言** 作为游戏逻辑语言，通过 hook 式接口与引擎交互，处理所有游戏逻辑，支持热更新和动态内容扩展

这种架构实现了"不同层次玩家各司其职"的目标，同时确保了：

- **高性能**：核心逻辑使用Rust静态编译
- **跨平台**：平台抽象层屏蔽差异
- **可扩展**：插件机制和Mod脚本提供灵活性
- **热更新**：HMR支持运行时内容迭代
- **开发友好**：脚本语言提供灵活易用的游戏开发环境

无论你是先知（引擎开发者，使用Rust）、执权者（游戏设计师，使用脚本）还是寻求灵知的玩家（Mod作者，使用脚本），都能在这个框架中找到自己的位置。

通过这种明确的语言分工，GG游戏引擎既保证了底层的性能和稳定性，又提供了上层的灵活性和开发效率，为游戏开发提供了一个理想的平台。
