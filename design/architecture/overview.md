# 架构概览

本项目是一个元游戏引擎框架，定位为编译时框架，通过插件组合机制生成具体的游戏引擎，支持多平台分发。在诺斯替（Gnostic）宇宙观的隐喻下，**太一（gwg）** 是超越的源头，**德穆革（具体游戏引擎）** 是有限的世界造物主，**执权者（游戏创造者）** 管理各自的世界，共同构建一个可扩展的游戏创造宇宙。

> 关于 Gnostic 神话隐喻的详细解释，请参考 [Gnostic 架构文档](/gnostic/overview)。

## 元引擎作为编译时框架的总体架构

元引擎框架采用静态与动态分离的设计思想，分为三个层次，对应诺斯替神话中的三层宇宙结构：

```
┌──────────────────────────────────────────────────────────┐
│                    元引擎框架 (编译时)                      │
│                    太一（The One）                          │
│  ┌────────────┐ ┌────────────┐ ┌────────────┐           │
│  │ ECS核心    │ │ 资源系统    │ │ 虚拟机(gwg) │           │
│  └────────────┘ └────────────┘ └────────────┘           │
│  ┌────────────────────────────────────────────────────┐ │
│  │                 插件注册与组合机制                    │ │
│  └────────────────────────────────────────────────────┘ │
└──────────────────────────────────────────────────────────┘
                              │
          (资深玩家选择插件，编译生成具体引擎)
                              ▼
┌──────────────────────────────────────────────────────────┐
│                   具体游戏引擎 (静态可执行文件)              │
│                   德穆革（Demiurge）                        │
│  ┌─────────────┐ ┌─────────────┐ ┌─────────────┐        │
│  │ Galgame插件 │ │ STG插件      │ │ 基础UI插件   │ ...    │
│  │ (静态链接)   │ │ (静态链接)   │ │ (静态链接)   │        │
│  └─────────────┘ └─────────────┘ └─────────────┘        │
│        内置编辑器（可选） + 运行时（ECS调度器）              │
└──────────────────────────────────────────────────────────┘
                              │
          (普通/高级玩家创作内容，动态加载)
                              ▼
┌──────────────────────────────────────────────────────────┐
│                      游戏实例 (运行时)                      │
│              物质世界（Kosmos）+ 普累若麻（Pleroma）        │
│  ┌────────────────────────────────────────────────────┐ │
│  │ 游戏项目（由DLC/Mod构成）                            │ │
│  │  ├─ 引擎配置文件（如 screen_size, default_font）    │ │
│  │  ├─ 资源包（图片、音频、剧本文件等）                  │ │

│  │  └─ Mod脚本（gwg代码，可注册系统/修改组件）           │ │
│  └────────────────────────────────────────────────────┘ │
│                    HMR补丁（实时更新）                     │
└──────────────────────────────────────────────────────────┘
```

### 各层次职责

#### 1. 元引擎框架（太一）
- **ECS核心**：万物生成的基始，一切实体与关系的雏形
- **资源抽象**：未成形的原质（如影像、音声），等待被赋予形式
- **虚拟机（gwg）**：灵性知识得以传播的媒介
- **平台抽象层**：太一的"遍在性"，使其能显现于不同物质载体
- **插件注册与组合机制**：流溢的通道

#### 2. 具体游戏引擎（德穆革）
- 由资深玩家使用元引擎框架，选择一组插件静态编译而成
- 包含编辑器模式（创造工具）和运行时模式（世界法则）
- 每位德穆革拥有固定的能力范围（如Galgame、STG、横版闯关）

#### 3. 游戏实例（游戏世界）
- **编辑端**：灵性蓝图，执权者在此进行创造
- **运行时客户端**：物质显现，玩家直接体验的世界
- **服务器端**（可选）：宇宙法则，维持多人世界的真实性与连续性

### 平台抽象层职责

平台抽象层屏蔽操作系统和运行环境的差异，为上层提供统一接口，包含以下子模块：

- **文件系统抽象**：统一接口访问各平台存储
- **输入抽象**：统一处理按键、鼠标/触摸、游戏手柄等事件
- **渲染抽象**：基于 `wgpu` 统一图形渲染
- **音频抽象**：统一播放控制，支持常见格式
- **时间与线程抽象**：统一获取系统时间、休眠、线程生成
- **动态链接与虚拟机支持**：确保 gwg 虚拟机能在目标平台运行

### 各平台分发形态

| 平台        | 分发形式                                    | 说明                                                                 |
| ----------- | ------------------------------------------- | -------------------------------------------------------------------- |
| Windows     | `.exe` 安装程序或便携版                     | 包含所有插件和运行时，可独立运行                                   |
| macOS       | `.app` 或 `.dmg`                            | 需签名以通过 Gatekeeper                                            |
| iOS         | `.ipa`（通过 TestFlight 或 App Store）       | 需 Apple 开发者证书；游戏数据包需通过 iTunes 文件共享或 App 内下载 |
| Android     | `.apk` 或 `.aab`（Google Play）              | 需签名；支持外部存储读取游戏数据包                                 |
| H5          | 静态文件（HTML + JS + WASM）                 | 部署在 Web 服务器上，通过浏览器访问                                |
| 微信小游戏  | 小游戏代码包（包含 WASM 和适配层 JS）        | 需通过微信小游戏审核，遵循小游戏规范                               |

**依赖关系核心原则**：

- 上层（工厂生成的编辑器/运行时）只依赖**基础模块**和**选定插件**。
- 基础模块之间通过**trait 抽象**解耦（例如 `gg-runtime-gfx` 依赖 `gg-core` 定义的 `Renderer` trait，而非具体后端）。
- 官方插件必须实现 `gg-core` 中对应的 `Plugin` trait，以便被引擎工厂动态加载和组合。

## 元引擎的组合生成机制：引擎工厂

### 引擎清单（Engine Manifest）

每个由元引擎生成的游戏引擎实例都由一个**声明式配置文件**定义，我们称之为**引擎清单**。该清单包含：

- **基础元数据**：名称、版本、目标游戏类型。
- **模块选取**：
  - 游戏对象模型模块（例如 `GOM.VisualNovel` 或 `GOM.ARPG`）。
  - 脚本运行时模块（例如 `VM.Lua` 或 `VM.Wasm` 或 `VM.BehaviorTree`）。
  - 渲染前端模块（例如 `Render.SpriteStack` 或 `Render.Immediate2D`）。
- **工具链扩展点**：声明编译器中需要启用的自定义处理步骤、编辑器中需要加载的面板与视图。
- **平台AOT后端列表**：例如 `windows-x64`, `web-wasm`, `android-arm64`。

元引擎的**引擎工厂**读取此清单，动态生成三个产物：

1. **定制编译器**（命令行工具或库）。
2. **定制编辑器**（IDE的插件包或独立应用骨架）。
3. **定制运行时**（一组静态库与引导代码）。

开发者也可以在此基础上进行**增量修改**——清单本身也支持继承与补丁，从而快速从"横板过关引擎"变种出"类银河城特化引擎"。

### 游戏对象模型的元描述

元引擎最关键的部分是**GOM Schema**——用一种与语言无关的接口定义语言（类似Protobuf/FlatBuffers + 行为标注）描述游戏世界中的实体、组件、事件与系统。

例如，对于RPG引擎，GOM可能包含：

```
entity Player {
  components: [Transform, Health, Inventory, SkillSet]
}

entity NPC {
  components: [Transform, DialogueTree, Vendor]
}
```

元编译器根据GOM Schema自动生成：
- 类型安全的C++/Rust/TypeScript数据结构（用于运行时和编辑器）。
- 序列化/反序列化代码（用于存档、网络同步、热重载状态迁移）。
- 编辑器的属性面板与资源选择器UI片段。
- 脚本绑定代码（用于Lua/Wasm与核心引擎交互）。

因此，**定义GOM就是定义一半的游戏引擎**。元引擎提供了高度可扩展的GOM编辑器，允许引擎开发者可视化地设计组件、事件流，并自动获得编辑器和运行时的支持。

## 设计原则

### 1. ECS作为统一核心

借鉴Unity的DOTS架构，所有游戏逻辑最终都通过ECS系统执行，确保性能和数据驱动。ECS世界提供统一的实体、组件、系统模型，所有插件和Mod都基于此模型交互。

### 2. WASM作为脚本虚拟机

类似于Godot的GDExtension，但更安全、跨平台。脚本在沙箱中运行，不能直接访问内存。通过导入函数暴露ECS API，确保安全可控。

### 3. 插件化架构

参考Unreal的模块系统，每个功能模块独立编译，引擎构建时静态链接，保证运行时性能。插件之间通过ECS世界通信，实现松耦合。

### 4. 平台抽象层

借鉴Godot的跨平台设计，通过trait抽象各平台差异，上层代码无需关心底层实现。平台抽象层包含文件系统、输入、渲染、音频、时间与线程等子模块。

### 5. 两层monorepo结构

避免目录过深，同时保持模块清晰。`crates/`下按功能领域划分，每个领域内部再按具体模块细分。

### 6. 静态与动态分离

- 编译时：元引擎框架 + 插件组合 → 生成具体引擎可执行文件
- 运行时：游戏数据包 + DLC/Mod → 动态加载，无需重新编译引擎

### 7. 不同层次玩家各司其职

- **普通玩家**：通过配置数据和编写剧本（DLC）就能创作游戏，无需编程
- **高级玩家**：使用虚拟机脚本（gwg）编写Mod，实现更复杂的自定义逻辑
- **资深玩家**：基于元引擎框架开发新的引擎插件或全新引擎（Rust代码），静态编译后发布

通过Gnostic神话的透镜，gwg元引擎架构展现出深层的象征结构：太一作为超越源头，德穆革作为有限造物主，执权者作为世界管理者，玩家作为灵性寻求者。每一层都既独立又相连，共同构成一个可扩展、跨平台的游戏创造宇宙。

这种架构实现了"不同层次玩家各司其职"的目标，同时确保了：
- 高性能：核心逻辑使用Rust静态编译
- 跨平台：平台抽象层屏蔽差异
- 可扩展：插件机制和Mod脚本提供灵活性
- 热更新：HMR支持运行时内容迭代

无论你是先知（引擎开发者）、执权者（游戏设计师）还是寻求灵知的玩家（Mod作者），都能在这个框架中找到自己的位置。
