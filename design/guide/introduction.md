# 简介

GG (Game Work Generator) 是一个**元游戏引擎框架**，定位为**编译时框架**，最终产出的是一个个独立的游戏引擎（每个包含编辑器与运行时）。这里的"元"有两层含义：

1. **引擎的引擎**——它本身不是一个直接制作游戏的工具，而是用于**生成、配置、组装**具体领域专用游戏引擎的**框架与工坊**。
2. **自反性与可扩展性**——元引擎的所有组成部分（编译器、编辑器、运行时）都被设计为可被替换、扩展、组合的模块，甚至元引擎自身的开发工具链也是用同样的插件体系构建的。

GG 采用 ECS (Entity-Component-System) 作为核心架构，结合 gg vm/Valkyrie script 实现灵活的脚本扩展，支持多平台分发。WASM/WASI 已降级为运行时。

## 设计理念：不同层次玩家各司其职

GG 的核心理念是让不同技能水平的玩家都能参与游戏创作，各展所长：

- **普通玩家**：通过配置数据和编写剧本（DLC）就能创作游戏，无需编程
- **高级玩家**：使用虚拟机脚本（gg）编写 Mod，实现更复杂的自定义逻辑
- **资深玩家**：基于元引擎框架开发新的引擎插件或全新引擎（Rust 代码），静态编译后发布

这种分层设计确保了从简单到复杂的游戏创作需求都能得到满足。

## Gnostic 神话隐喻

在 Gnostic 架构中，gg 元引擎框架被映射为诺斯替（Gnostic）宇宙观：

| 诺斯替概念 | 架构组件 | 职责描述 |
|----------|---------|---------|
| **太一（The One）** | gg（元引擎框架） | 不可名状的绝对本源，超越一切限定，通过流溢产生德穆革。在编译时静态存在，提供所有潜能。 |
| **德穆革（Demiurge）** | 具体游戏引擎（静态可执行文件） | 由太一流溢而出，按照某种理念（插件组合）创造并统治特定的游戏世界。 |
| **执权者（Archons）** | 游戏创造者（开发者/设计师） | 德穆革的助手，掌管不同领域。他们使用德穆革提供的工具（编辑器）来设计具体的游戏世界。 |
| **普累若麻（Pleroma）** | 游戏项目（数据与脚本的总和） | 充满灵性的完整性领域，包含所有潜在的实体与事件。 |
| **物质世界（Kosmos）** | 运行时客户端（Runtime） | 玩家直接体验的显现世界，是普累若麻在物质层面的投影。 |

> 关于 Gnostic 神话隐喻的详细解释和完整映射，请参考 [Gnostic 架构文档](/gnostic/overview)。

## 目标用户群体

### 普通玩家
- **技能要求**：无需编程基础
- **创作方式**：配置数据、编写剧本、使用编辑器
- **产出**：完整的游戏项目（纯数据包）
- **工作场景**：使用编辑器可视化编辑剧情、场景、资源，通过 DLC 扩展游戏内容

### 高级玩家
- **技能要求**：基础编程知识
- **创作方式**：编写 gg 脚本 Mod
- **产出**：可扩展游戏逻辑的 Mod 脚本
- **工作场景**：监听事件、创建新实体、修改组件数据、注册自定义系统

### 资深玩家
- **技能要求**：Rust 编程、游戏引擎开发经验
- **创作方式**：开发引擎插件、构建具体引擎
- **产出**：独立的游戏引擎可执行文件
- **工作场景**：编写 Rust 插件、组合引擎构建器、生成多平台分发包

## 核心功能模块概览

### 1. 元引擎框架（编译时）
- **ECS 核心 (gg-ecs)**：基于 `bevy_ecs` 的高性能实体组件系统
- **资源管理系统 (gg-asset)**：支持异步加载、热重载，与具体文件格式解耦
- **虚拟机集成 (gg-vm)**：嵌入轻量级脚本运行时，定义安全的 Rust-脚本通信接口
- **调度器 (gg-schedule)**：系统调度器扩展
- **世界管理 (gg-world)**：世界管理
- **反射系统 (gg-reflection)**：反射系统
- **类型定义 (gg-types)**：共享类型定义
- **宏定义 (gg-macros)**：实用宏，简化开发

### 2. 运行时层
- **中间表示 (gg-ir)**：中间表示
- **虚拟机 (gg-vm)**：虚拟机执行环境

### 5. 多平台支持
- **桌面平台**：Windows、macOS、Linux
- **移动平台**：iOS、Android
- **Web 平台**：H5 (WASM + HTML)
- **小游戏平台**：微信小游戏
