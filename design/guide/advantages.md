# 元游戏引擎核心优势

## 1. ECS 核心架构的高性能与数据驱动

元游戏引擎采用 Entity-Component-System（ECS）作为核心架构，为游戏开发带来卓越的性能和灵活性。

### 性能优势
- **数据局部性优化**：组件按类型连续存储，最大化 CPU 缓存命中率，相比传统面向对象架构可获得数倍性能提升
- **并行调度能力**：系统间天然无依赖，可自动并行执行，充分利用多核 CPU 资源
- **内存高效**：稀疏组件存储模式，仅为实际使用的实体分配内存

### 与主流引擎对比
| 特性 | 元引擎 | Unity | Unreal | Godot |
|-----|-------|-------|--------|-------|
| **核心架构** | 纯 ECS 优先 | GameObject (ECS可选) | Actor (UObject) | 场景树 |
| **数据驱动** | 完整支持 | 有限支持 | 强类型系统 | 脚本驱动 |
| **并行调度** | 原生支持 | 需 DOTS 配置 | 需手动优化 | 单线程为主 |

### 实践价值
所有游戏逻辑最终都通过 ECS 系统执行，确保从引擎开发到游戏创作的完整性能一致性。无论是 Galgame、STG 还是其他类型游戏，都能享受统一的高性能运行时。

## 2. 多平台支持特性

元游戏引擎通过精心设计的平台抽象层，实现真正的"一次编写，到处运行"。

### 支持的平台
- **桌面**：Windows、macOS、Linux
- **移动端**：iOS、Android
- **Web**：H5（WebAssembly）、微信小游戏

### 平台抽象层能力
| 抽象模块 | 说明 |
|---------|------|
| **文件系统** | 统一接口屏蔽沙盒限制、Web HTTP 加载、小游戏缓存差异 |
| **输入系统** | 统一处理键盘、鼠标、触摸、游戏手柄事件 |
| **图形渲染** | 基于 wgpu，支持 Vulkan/Metal/DX12/WebGL2 |
| **音频系统** | 统一播放控制，支持 MP3、OGG、WAV 等格式 |
| **时间线程** | 跨平台时间获取，Web 环境异步任务模拟 |

### 分发形态
| 平台 | 分发形式 | 说明 |
|-----|---------|------|
| Windows | `.exe` | 包含所有插件和运行时 |
| macOS | `.app/.dmg` | 需签名通过 Gatekeeper |
| iOS | `.ipa` | TestFlight 或 App Store |
| Android | `.apk/.aab` | Google Play 或直接安装 |
| H5 | HTML+JS+WASM | 部署在 Web 服务器 |
| 微信小游戏 | 小游戏代码包 | 包含 WASM 和适配层 |

## 3. 插件化架构的灵活性

元游戏引擎采用编译时插件组合机制，提供极致的灵活性和性能。

### 插件系统特性
- **静态链接**：所有插件在编译时链接，无运行时开销
- **功能模块化**：渲染、音频、物理、UI 等完全独立
- **依赖管理**：插件间可声明依赖关系
- **编辑器集成**：插件可自动暴露编辑界面

### 典型插件组合示例
```rust
// Galgame 引擎组合
EngineBuilder::new()
    .add_plugin(RenderPlugin::new_2d())
    .add_plugin(AudioPlugin::default())
    .add_plugin(UIPlugin::default())
    .add_plugin(GalgamePlugin::new())
    .with_editor(true)
    .build()
    .run();
```

### 与主流引擎对比
| 特性 | 元引擎 | Unity | Unreal | Godot |
|-----|-------|-------|--------|-------|
| **组合方式** | 编译时静态链接 | 运行时动态加载 | 模块系统 | 插件系统 |
| **性能** | 零运行时开销 | 有加载开销 | 需手动优化 | 脚本层开销 |
| **灵活性** | 完全定制 | 预定义架构 | 庞大架构 | 场景树限制 |

## 4. WASM 虚拟机的安全性和跨平台性

元游戏引擎将 WebAssembly (WASM) 作为脚本虚拟机，实现安全、跨平台的 Mod 扩展。

### 安全特性
- **沙箱隔离**：脚本无法直接访问宿主内存
- **API 受控**：仅暴露预定义的安全接口
- **权限管理**：可精细控制脚本访问范围

### 跨平台能力
- **一次编译，到处运行**：WASM 字节码可在所有平台执行
- **多后端支持**：
  - 桌面：Wasmtime (JIT)
  - 轻量：Wasmi (解释器)
  - Web：浏览器原生支持
  - 小游戏：自定义 JS 胶水层

### 脚本 API 能力
Mod 脚本可以：
- 查询和遍历实体
- 创建/销毁实体
- 添加/移除/修改组件
- 发送和监听事件
- 注册自定义系统

### 与主流脚本对比
| 特性 | 元引擎 (WASM) | Unity (C#) | Unreal (C++/Blueprint) | Godot (GDScript) |
|-----|---------------|-----------|------------------------|-----------------|
| **安全性** | 沙箱隔离 | 受限访问 | 完全访问 | 受限访问 |
| **跨平台** | 完美 | 需 IL2CPP | 需重新编译 | 需解释 |
| **性能** | 接近原生 | 较好 | 最佳 | 一般 |

## 5. HMR 热更新的开发效率

元游戏引擎内置完整的热模块替换 (HMR) 机制，大幅提升开发效率。

### 支持的热更类型
| 类型 | 说明 |
|-----|------|
| **资源热更** | 图片、音频、字体等实时重载 |
| **数据热更** | 剧本、配置文件更新 |
| **脚本热更** | Mod 脚本重新加载 |

### 各平台 HMR 支持
| 平台 | 支持程度 | 实现方式 |
|-----|---------|---------|
| 桌面 | 完全支持 | 文件监视器 + 资源重载 |
| iOS/Android | 开发版支持 | USB 调试或网络推送 |
| H5 | 开发版支持 | WebSocket 通知 |
| 微信小游戏 | 不支持 | 需发新版 |

### HMR 工作流程
1. 文件监视器检测到变更
2. 根据文件类型分发到对应管理器
3. 管理器应用更新
4. 发送 ECS 事件通知相关系统
5. 系统响应事件，刷新 UI 或游戏状态

### 开发效率提升
- **无需重新编译**：资源和数据变更即时生效
- **无需重启游戏**：保持当前游戏状态测试变更
- **快速迭代**：剧本、UI、数值调整即时反馈

## 6. Monorepo 结构的代码组织优势

元游戏引擎采用两层 Monorepo 结构，既保持模块清晰，又避免目录过深。

### 目录结构设计
```
gwg-engine/
├── crates/                    # 第一层：功能领域
│   ├── frameworks/            # 核心框架层
│   │   ├── gwg-ecs/          # ECS 核心封装
│   │   ├── gwg-asset/        # 资源管理
│   │   ├── gwg-schedule/     # 系统调度器扩展
│   │   ├── gwg-world/        # 世界管理
│   │   ├── gwg-reflection/   # 反射系统
│   │   ├── gwg-types/        # 类型定义
│   │   └── gwg-macros/       # 宏定义
│   ├── runtime/               # 运行时层
│   │   ├── gwg-ir/           # 中间表示
│   │   └── gwg-vm/           # 虚拟机
└── tools/                     # 构建工具
```

### 模块依赖关系
```
frameworks (ecs/asset/schedule/world/reflection)
    ↓
runtime (ir/vm)
```

### Monorepo 优势
| 优势 | 说明 |
|-----|------|
| **统一依赖管理** | 所有 crate 共享版本，避免依赖冲突 |
| **代码共享** | 公共逻辑可轻松提取复用 |
| **原子提交** | 跨模块修改可一次提交 |
| **统一构建** | 一条命令构建所有模块 |
| **清晰边界** | 两层结构避免目录过深，保持可读性 |

## 总结

元游戏引擎通过六大核心优势，为不同层次的玩家提供完整的游戏创作体验：

- **资深玩家**：基于 ECS 核心和插件框架开发新引擎
- **高级玩家**：通过 WASM 脚本编写 Mod 扩展游戏逻辑
- **普通玩家**：通过数据配置和剧本创作游戏，无需编程

所有层通过 ECS 世界紧密耦合，最终实现"一次编写引擎，到处运行游戏"的目标。
