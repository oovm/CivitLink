# GG 游戏引擎文档风格指南

## 1. 文档结构

### 1.1 目录结构

- **design/core/**: 核心模块文档，包括 ECS、资源系统、反射系统、调度器、世界管理等
- **design/architecture/**: 架构文档，包括架构概览、分层架构、子系统等
- **design/platforms/**: 平台相关文档，包括各平台实现细节
- **design/compiler/**: 编译器相关文档
- **design/editor/**: 编辑器相关文档
- **design/engines/**: 具体游戏引擎文档，如 Galgame、STG、Platformer 等
- **design/formats/**: 文件格式文档
- **design/guide/**: 使用指南文档
- **design/gnostic/**: Gnostic 架构隐喻文档

### 1.2 文档结构

每个文档应包含以下结构：

1. **标题**：使用 `#` 标记一级标题
2. **概述**：简要介绍文档内容
3. **核心概念**：解释文档中涉及的核心概念
4. **核心类型**：描述主要的数据结构和类型
5. **使用示例**：提供代码示例
6. **相关模块**：列出相关的模块文档

## 2. 格式规范

### 2.1 标题

- 使用 Markdown 标题语法
- 一级标题：`# 标题`
- 二级标题：`## 标题`
- 三级标题：`### 标题`
- 四级标题：`#### 标题`

### 2.2 代码块

- 使用 triple backticks 包围代码块
- 指定代码语言，如 ```rust
- 代码示例应简洁明了，展示核心功能
- 代码应包含必要的注释

### 2.3 表格

- 使用 Markdown 表格语法
- 表格标题应清晰明了
- 表格内容应对齐

### 2.4 列表

- 使用 `-` 标记无序列表
- 使用数字标记有序列表
- 列表项应简洁明了

### 2.5 链接

- 使用 Markdown 链接语法：`[链接文本](链接地址)`
- 内部链接使用相对路径
- 外部链接应包含完整 URL

## 3. 语言规范

### 3.1 术语

- 使用一致的术语
- 首次出现的术语应定义
- 避免使用歧义性术语

### 3.2 风格

- 使用简洁明了的语言
- 避免使用过于 technical 的术语
- 使用主动语态
- 保持文档风格一致

### 3.3 代码风格

- 代码示例应遵循 Rust 代码风格
- 变量名应使用 snake_case
- 类型名应使用 PascalCase
- 函数名应使用 snake_case
- 常量应使用 SCREAMING_SNAKE_CASE

## 4. 内容规范

### 4.1 文档内容

- 文档应准确反映实际代码实现
- 文档应包含足够的细节，便于理解
- 文档应避免自相矛盾的内容
- 文档应定期更新，与代码保持同步

### 4.2 示例代码

- 示例代码应可运行
- 示例代码应包含必要的导入语句
- 示例代码应展示核心功能
- 示例代码应包含注释，解释关键部分

### 4.3 图表

- 使用 Mermaid 语法创建图表
- 图表应清晰明了
- 图表应与文档内容一致

## 5. 版本控制

### 5.1 文档更新

- 文档应与代码同步更新
- 重大架构变更应更新相关文档
- 文档更新应包含变更说明

### 5.2 文档审核

- 文档应定期审核，确保准确性
- 新文档应经过审核后发布
- 文档审核应关注内容准确性和一致性

## 6. 工具和资源

### 6.1 工具

- 使用 Markdown 编辑器编写文档
- 使用 Mermaid 生成图表
- 使用代码格式化工具确保代码示例格式一致

### 6.2 资源

- 参考其他成熟游戏引擎的文档结构
- 参考 Rust 官方文档风格
- 参考 Markdown 最佳实践

## 7. 总结

本风格指南旨在确保 GG 游戏引擎文档的一致性、准确性和可读性。所有文档维护者应遵循本指南，确保文档质量。文档是引擎的重要组成部分，良好的文档将有助于开发者理解和使用引擎。
